# 双语审阅（阶段一）

范围：中文操作界面、三版英文推文及忠实中译。阶段一提交后等待验收；配图生成属于阶段二，本阶段不实现。

## 字段与接口

- `text`：唯一复制到剪贴板并写入台账 `finalText` 的正文，保持英文和现有 280 字符上限。
- `zh_summary`：中文忠实对照译文，保留原文数字、单位、时间、否定、条件和确定程度，不是摘要。
- `angle`：中文版本角度标题。
- `whyItWorks`：中文表达策略，基于初稿，不作为翻译；英文编辑后明确标注为“基于初稿”。

`POST /api/generate` 在同次请求中生成三版及四个字段；中文字段必须非空并包含中文字符，正文单独进行英文检查。三版生成输出预算为 3000 tokens，保留一次格式修复重试。修复请求同时包含原始输入及有问题的输出。

`POST /api/translate` 输入 `{ "text": "当前英文正文" }`，输出 `{ "data": { "text": "完全相同的输入正文", "zh_summary": "中文对照" } }`。原文由服务器回传，不由模型改写；模型只返回 `zh_summary`。使用相同 DeepSeek provider 和服务端 key，temperature 为 0，最多修复一次。

字符和语言检查只验证格式，不能证明译文语义绝对准确。提示词明确保留数字、否定、条件及语气，并用真实请求进行人工对照验收；不把测试桩结果等同于模型准确性保证。

## 同步规则

每张卡片保存“该译文对应的英文”。当前编辑文本与之不一致时显示：**英文已修改，中文对照待更新**。旧译文保留，注明对应修改前正文。

1. 点击更新只提交该卡片的当前英文，不重新生成推文。
2. 编辑立即使该卡片进行中的请求失效；允许为新正文重新发起更新。
3. 同卡片最新有效请求才能更新译文；其他版本及旧批次的响应和错误不影响当前卡片。
4. 响应回传的英文必须与请求正文完全一致，否则保留旧译文并提示重试。
5. 撤销编辑恢复到译文对应的英文时，自动恢复同步状态，无需请求。
6. 生成或翻译失败保留已有英文、中译和编辑状态。
7. 每批草稿固定生成时的素材及内容类型；后续修改输入表单不会改变旧草稿的台账归属。

更新中译不写入台账。复制仍先写剪贴板，成功后仅将英文正文作为 `finalText` 入账。历史数据无需迁移；本阶段不增加运行数据文件。

## 验收

自动测试使用模拟 DeepSeek 和隔离临时台账：字段缺失/空值/语言边界、一次请求返回完整双语结果、原文保留至重试、复制入账无中文辅助字段、各版本独立更新、编辑后迟到响应/错误、重生成批次隔离、失败重试及素材归属。

浏览器操作：

1. 在 X 生成器输入中文事实素材，生成三版，检查英文正文和三类中文字段。
2. 将第一版改成含数字、条件和否定的英文，例如：`If a match asks for $750 within 48 hours, it may indicate pressure. It does not prove fraud, and declining one video call is not proof either.`
3. 检查仅第一版出现过期提示，旧译文未被清空。
4. 点击“更新中文对照”，检查英文原样保留，中译含 750 美元、48 小时、可能，以及两处否定；其他两版不变。
5. 检查桌面与窄屏中文区域、按钮、英文换行及控制台。

检查命令：`npm test`、`npm run typecheck`、`npm run lint`、`npm run build`（均在 `/ops` 下）。
